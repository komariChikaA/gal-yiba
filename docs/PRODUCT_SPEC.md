# 产品范围（第一阶段）

## 核心体验

系统随机选择一部视觉小说作为答案。玩家搜索并提交作品后，服务端按本局启用的比较项返回结构化判定；界面只用绿色、黄色、灰色和斜纹展示状态，需要时附加 `+ / − / ↑ / ↓`，不再显示重复的文字结论。玩家在有限次数或时间内猜中答案。

参考站提供了单人随机题、每日题、难度题池和固定的比较列。本项目保留清晰的推理反馈，但把比较列与题池标签改为房间规则，不把固定 13 列写死进游戏逻辑。

## 第一阶段范围

1. 三种模式：单人随机题、1v1 对战、2–8 人同时竞技；支持房间加入、准备、同步开始、退出、结算与短时重连。
2. 房主配置：比较项、题池标签、知名度档位、剧透等级、是否只使用全年龄作品。
3. 数据：VNDB 与 Bangumi 的来源记录分开保存，通过可审核映射关联为站内作品。
4. 管理审核页保留为下一迭代。

## 暂不在第一阶段承诺

- 大规模随机匹配、全球排行榜和复杂反作弊。
- 直接复制或镜像第三方图片、简介、评论和用户数据。
- 自动认定所有 VNDB 与 Bangumi 同名条目为同一作品。
- 用外部 API 作为每次猜测的实时依赖。

## 当前实现决策（可在后续讨论中调整）

- “选择标签”同时支持选择比较列和筛选答案题池的作品标签。
- 多人首发采用所有人同题竞速；首位猜中者赢得本轮。房主可把赛制改为三局两胜、五局三胜或七局四胜，服务端累计各轮胜场并在达标后决出整场胜者。
- 每日同题全员共用一个按日期确定的答案，当日首次生成后锁定，不随题库同步变化。
- 1v1 只公开双方已用次数的星号进度，不公开对手提交的作品；开局后入口与规则区退出视野，答题区直接置顶。
- 知名度采用累进 Top-N 题池：前 500 部只从 Bangumi 评分与票数完整的作品中按 Bangumi 票数排序，因此萌新 100、入门 250、标准 500 均可使用 Bangumi 两项比较；小资历 750、老资历 1024 再按综合分补齐，默认标准。
- 默认比较项为开发会社、女主发色、两库独立评分与票数、年份、时长、动画化、全年龄、平台和标签。
- 平台比较将 Windows/Linux/macOS 等归并为 PC，并合并同一主机家族；已有 PC 或主要主机时忽略小众、Android、iOS、Web 平台，完全没有主要平台时才回退到其他平台，单部作品最多展示 4 个。
- 作品标签先统一成简短中文概念，排除技术、成人内容和过细标签，再按房间允许的剧透等级与来源重要度选取前三个参与题池筛选和猜测比较。
- “女主发色”读取 VNDB 中该作品的非剧透 `primary` 女性角色；多名主要女角色保留颜色集合，不主观指定唯一第一女主。
- “脚本家”使用 VNDB 登记的 `scenario` 担当集合，优先显示日文 `original` 原名；来源不提供主次顺序，因此界面明确提示该限制。
- 详细的绿色、黄色、`+ / − / ↑ / ↓` 规则与当前题库分布见[比较规则](COMPARISON_RULES.md)。
- 搜索覆盖作品标题、别名和开发会社；模糊结果必须标明命中字段。
- 默认隐藏有剧透标签，但答案池包含所有年龄分类；房主可单独开启“只要全年龄游戏”。乙游默认不进入题池，房主开启“乙游（女性向恋爱）”后才会纳入。
- GitHub 仓库确定为公开的 `komariChikaA/gal-yiba`；软件许可证和正式域名仍待确认。
