# 标签与脚本家姓名规范

## 作品标签

游戏判定层不直接展示来源库的全部原始标签，而是把 VNDB 与 Bangumi 的同义标签归并到一组简短中文概念。示例：

| 来源写法                                            | 站内统一写法 |
| --------------------------------------------------- | ------------ |
| `Science Fiction`、`Sci-Fi`、`SF`、`科幻`           | 科幻         |
| `School`、`High School`、`校园`、`学园`             | 校园         |
| `Slice of Life`、`Daily Life`、`日常`               | 日常         |
| `Girl x Girl Romance`、`Girls Love`、`Yuri`、`百合` | 百合         |

每部作品只按来源重要度选前三个已归一标签。未收录的英文标签不会直接显示；角色外貌、胸围、具体亲属关系、单个剧情机关等过细标签也不会进入代表标签。VNDB 的 `ero` 与 `tech` 分类全部排除，因为成人分级、平台等已经有独立判定列。原始标签仍保存在来源记录中，后续可以审核并扩充归一表。

Bangumi 标签是社区标签，可能包含公司名、年份、平台、汉化组或主观评价。只有能稳定归入站内概念表的标签才参与判定，避免不同来源产生两套近义标签。

## 脚本家姓名

脚本家仍以 VNDB 作品条目登记的 `scenario` 担当为准。同步时同时请求 `name`、`original` 与 `lang`：

1. 有 `original` 时优先展示原文字段；日文姓名会移除姓与名之间仅用于排版的空格，例如 `麻枝 准` 显示为 `麻枝准`。
2. 原文字段缺失时保留 VNDB 登记名，不对人名做机器翻译或凭读音造中文名。
3. 已有来源记录会保留；重新同步 VNDB 后，新字段会进入规范化记录。
4. 如需补充公认中文译名，必须按 VNDB staff ID 维护人工校对表并记录可靠来源，不用模糊字符串替换。

依据：[VNDB API v2](https://api.vndb.org/kana) 明确说明作品的 `staff.*` 可使用全部 staff 字段，`original` 是原文字体姓名；标签分类为内容 `cont`、成人内容 `ero` 与技术 `tech`。[Bangumi API](https://github.com/bangumi/api) 提供条目公开标签，但标签来自社区，站内只把它作为可归一的辅助来源。
