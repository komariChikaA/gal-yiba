# 第一阶段验收清单

验收范围对应当前项目目标：可部署的 Galgame 猜谜网站、VNDB/Bangumi 双来源题库、单人/1v1/多人三种模式、每日同题，以及房主可配置比较项、知名度、答案标签和赛制（单局/三局两胜/五局三胜/七局四胜）。排行榜、管理网页和多实例扩容属于后续路线，不作为本阶段完成条件。

## 要求与证据

| 要求            | 当前证据                                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| 猜谜核心体验    | `packages/shared/src/game.ts` 在服务端答案快照上生成猜测历史；`comparison.ts` 统一执行颜色、数量符号和方向判定 |
| VNDB 与 Bangumi | 两个适配器分别保存来源记录；只有 `verified` 的 Bangumi 映射进入规范题库，评分与票数不混合                      |
| 三种游戏模式    | Socket.IO 房间支持单人、严格 2 人的 1v1、2–8 人多人竞技；均使用服务端隐藏答案，并支持主动退出                  |
| 每日同题        | `game.ts` 提供按日期确定的答案选取，当日首次生成后由服务端锁定；`DailyRegistry` 按匿名令牌维护独立会话，`/api/daily` 提供隐藏答案的答题与猜测接口 |
| 对战进度与聚焦  | 1v1 左右显示本人/对手星号进度；开局后入口区与规则区不再占据首屏                                                |
| 对战倒计时      | 默认 5 分钟并支持 3/5/10 分钟房间规则；客户端实时显示，服务端到点自动将仍在答题的玩家结算为超时                |
| 多轮赛制        | 房主可选 1/3/5/7 局；服务端跨轮累计胜场，达到多数胜后决出整场胜者；对手离场或轮数用尽也会正常收场             |
| 同房间再来一局  | 房主可在结算界面发起 `room:rematch`，房间回到准备大厅并清空比分与轮次，原房间号/成员/规则保留      |
| 自选比较项      | 房主可从 15 项中选择至少 3 项；规则由服务端校验并同步给房间玩家                                                |
| 排行榜          | 客户端持有稳定玩家 ID（localStorage），比赛结束由 `MatchRecorder` 写入战绩；`/api/leaderboard` 支持按模式与数量筛选，前端面板高亮自己 | 
| 自选答案题池    | 支持萌新/标准/老资历知名度档、包含/排除标签、全部/任一匹配、剧透等级和“只要全年龄游戏”开关                     |
| 搜索作品与会社  | 搜索覆盖标题、全部别名和开发会社；强标题匹配在前，会社结果随后，弱模糊噪声受阈值限制                           |
| 可部署          | Docker Compose 启动应用、PostgreSQL 与 Redis；应用启动时执行幂等迁移并提供健康接口                             |
| 公开仓库安全    | `.env`、登录辅助文件、服务器地址和凭据不进入 Git 跟踪；部署配置只使用环境变量                                  |

## 自动验证

```bash
pnpm check
```

该命令依次执行全工作区类型检查、单元/集成测试与生产构建。2026-08-09 验收时共有 74 项测试通过。

有生产题库的运行环境可执行双客户端冒烟测试：

```bash
SERVER_URL=http://127.0.0.1:3000 pnpm --filter @gal-yiba/web smoke:game
```

测试覆盖创建房间、第二名玩家加入、防身份伪造、断线重连、准备、隐藏答案开局、搜索与猜测，并核对比较列数量、女主发色、主要平台及前三标签。

## 已知边界

当前房间状态位于单应用进程内，适用于用户现有的一台服务器。Redis 仅为后续多实例扩容预留；进程重启不会恢复进行中的房间。该限制不影响当前单实例线上对战，但部署方不应启动多个应用副本。
